# Синхронизация между устройствами

Приложение работает по принципу **offline-first**: данные всегда хранятся в
localStorage браузера, а Supabase используется только как слой синхронизации.
Если база недоступна (проект на паузе, нет сети, ключи не заданы) — приложение
продолжает работать, а изменения уедут в облако при следующей успешной связи.

## 1. Проект Supabase

Проект из `.env` (`gksabgzqysblvkiwmico`) стоит на паузе — поэтому его домен не
отвечает. Данные целы: https://supabase.com/dashboard → **Resume project**.
Восстановить его можно до **15 марта 2027**, после этой даты останется только
скачивание бэкапов.

URL и anon-ключ после восстановления не меняются — `.env` править не нужно.

Если всё же создаёте новый проект: **New project** →
**Project Settings → API** → скопировать **Project URL** и ключ **anon public**.

## 2. Таблица

**SQL Editor** → выполнить содержимое [supabase_schema.sql](supabase_schema.sql).

Создаётся одна таблица `user_data` (ключ → JSON) с RLS-политиками: каждый
пользователь видит только свои строки.

## 3. Вход по email и паролю

**Authentication → Providers → Email** — провайдер включён по умолчанию.

Если не хотите подтверждать email при регистрации, выключите
**Confirm email** в настройках провайдера — иначе после регистрации нужно будет
перейти по ссылке из письма.

OAuth (Google) не используется — именно из-за него ломались редиректы на
GitHub Pages.

## 4. Ключи

Локально — файл `.env` в корне:

```
VITE_SUPABASE_URL=https://<ваш-проект>.supabase.co
VITE_SUPABASE_ANON_KEY=<anon public ключ>
```

Для деплоя — **Settings → Secrets and variables → Actions** в репозитории
GitHub: секреты `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`
(их читает [.github/workflows/deploy.yml](.github/workflows/deploy.yml)).

## 5. Использование

1. На компьютере: **Профиль → Синхронизация → Создать аккаунт**.
2. На телефоне: открыть тот же адрес GitHub Pages и войти тем же email и паролем.
3. Данные подтянутся автоматически. Принудительно — кнопка 🔄 в шапке (видна
   после входа) или **Синхронизировать сейчас** в профиле.

Сессия сохраняется, повторно вводить пароль на телефоне не нужно.

## Как разрешаются конфликты

У каждого блока данных (финансовый план, настройки, профиль) есть своя метка
времени последнего изменения. При синхронизации побеждает более свежая версия
блока — целиком. Правки одного и того же блока с двух устройств без
синхронизации между ними не сливаются: сохранится та, что новее.

Практический вывод: перед вводом данных на втором устройстве стоит открыть
приложение и дождаться синхронизации.

## Если проект Supabase встал на паузу

Бесплатный тариф паузит проект после ~7 дней неактивности. Данные при этом
сохраняются — проект поднимается кнопкой **Resume project** в дашборде.
Домен приостановленного проекта не отвечает вообще, это нормально. Приложение в
это время работает локально и покажет в профиле сообщение о недоступности базы.

Дашборд указывает срок, до которого проект можно восстановить (для текущего —
15 марта 2027). После него данные остаются доступны только для скачивания.

Чтобы не зависеть от этого совсем, в разделе **Резервная копия** есть выгрузка
всех данных в JSON-файл и восстановление из него.
